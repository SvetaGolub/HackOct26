# Invoice Keeper API

Backend для учёта регулярных расходов и платежей компании. Сотрудники подают заявки на расходы, бухгалтеры рассматривают заявки и отмечают платежи, а администратор управляет пользователями и отделами. Сервис также поддерживает напоминания через Telegram и журнал изменений.

## Возможности

- Авторизация по email и паролю с JWT.
- Роли: администратор, бухгалтер и сотрудник; доступ к данным ограничен отделом.
- Заявки на расходы с одобрением и отклонением.
- Регулярные и разовые платежи в RUB, USD и EUR.
- Учёт периодов оплаты, просрочек и переносов сроков.
- Итоги по валютам без конвертации.
- Журнал изменений и напоминания Telegram.

## Требования

- Docker Desktop с работающим Docker Engine и поддержкой Linux-контейнеров.
- Telegram-бот, созданный через BotFather, и его токен.

## Запуск через Docker Compose

В PowerShell из корневой папки проекта создайте файл настроек:

```powershell
Copy-Item .env.example .env
notepad .env
```

Перед запуском измените значения-заглушки в `.env`:

| Переменная | Назначение |
| --- | --- |
| `DB_PASSWORD` | Пароль пользователя MySQL |
| `DB_ROOT_PASSWORD` | Пароль администратора MySQL |
| `JWT_SECRET_KEY` | Секретная строка для подписи токенов; задайте длинное случайное значение |
| `ADMIN_LOGIN` | Email системного администратора |
| `ADMIN_PASSWORD` | Пароль системного администратора |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `CORS_ORIGINS` | Разрешённые origin фронтенда через запятую, например `http://localhost:5173` |

Значения `ADMIN_LOGIN` и `ADMIN_PASSWORD` используются для создания системного администратора при запуске приложения. `ADMIN_LOGIN` должен быть email-адресом. Не используйте демонстрационные пароли в реальном окружении.

Соберите образ и запустите API вместе с MySQL:

```powershell
docker compose up --build -d
```

При старте контейнер приложения ждёт готовности MySQL, применяет миграции Alembic, затем запускает API и Telegram-бота. Посмотреть состояние и логи:

```powershell
docker compose ps
docker compose logs -f app
```

Остановить контейнеры, сохранив данные базы:

```powershell
docker compose down
```

Данные MySQL хранятся в Docker volume `dbdata`. Команда `docker compose down -v` удаляет этот volume вместе с данными базы.

## API

- Адрес API: `http://localhost:8000/api/v1`
- Swagger UI: `http://localhost:8000/api/v1/docs`
- OpenAPI JSON: `http://localhost:8000/api/v1/openapi.json`

Для защищённых запросов передавайте JWT в заголовке:

```http
Authorization: Bearer <accessToken>
```

Основные группы endpoints:

- `/auth` — вход, текущий пользователь и привязка Telegram.
- `/expense-requests` — заявки и их рассмотрение.
- `/recurring-payments` и `/payment-occurrences` — регулярные платежи и периоды оплаты.
- `/payments/summary` — суммы платежей по валютам.
- `/users`, `/departments`, `/audit-log` — пользователи, отделы и история изменений.

Доступные операции и схемы запросов смотрите в Swagger UI.

## Тесты

Нужны Python 3.14 и `uv`. Установите приложение с зависимостями для разработки и запустите тесты:

```powershell
uv sync --group dev
uv run pytest -q
```

Интеграционные тесты API используют отдельную временную SQLite-базу и не подключаются к базе из `.env` или Docker.
