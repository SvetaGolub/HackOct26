# Invoice Keeper — напоминания о регулярных платежах

Система, которая не даёт забыть о регулярных расходах: аренда, подписки, оплата серверов. Администратор (главный бухгалтер) вносит регулярные платежи, бот напоминает об оплате в Telegram за заданное число дней до срока (по умолчанию за 3 дня), пользователи (бухгалтеры) отмечают оплату и следят за просрочками.

## Возможности

- Авторизация по логину и паролю (JWT с отзывом сессии при выходе).
- Две роли:
  - **администратор** — задаётся через `.env`; добавляет и удаляет регулярные платежи, создаёт, меняет и удаляет обычных пользователей, а также может всё, что доступно пользователю;
  - **пользователь** — видит общий список платежей, отмечает и отменяет оплату, указывает и исправляет фактическую дату оплаты.
  Ограничения проверяются на сервере, поэтому действуют и в API.
- Регулярные платежи: название, сумма, валюта, дата ближайшей оплаты, периодичность (ежемесячно, еженедельно, ежегодно, ежедневно, через заданное число дней или разовый платёж). Если в месяце или году нет нужного числа, срок переносится на последний день.
- Каждый период — отдельная запись со своим сроком и отметкой «Оплачено / Не оплачено». Новый период не стирает прошлые оплаты, просрочка не останавливает следующие периоды.
- Просрочка начинается со следующего дня после срока; оплата в день срока — вовремя. При исправлении фактической даты просрочка пересчитывается, срок не меняется.
- Валюты RUB, USD, EUR; итоги считаются отдельно по каждой валюте, без конвертации.
- Telegram-бот: напоминание за `REMINDER_DAYS` (по умолчанию 3) дней до срока в указанный чат и лично пользователям с привязанным аккаунтом. Без дублей; оплаченный период и удалённый платёж напоминаний не создают; платёж, добавленный позже чем за 3 дня до срока, вызывает напоминание сразу. Отметка TG в календаре появляется после успешной отправки.
- Кнопка «Оплачено» прямо в сообщении бота (для привязанных пользователей).
- Журнал авторизации и действий (только администратор).

## Требования

- Docker Desktop с работающим Docker Engine и поддержкой Linux-контейнеров.
- Telegram-бот, созданный через BotFather, его токен и чат, в который бот может писать.

## Запуск через Docker Compose

В PowerShell из корневой папки проекта создайте файл настроек:

```powershell
Copy-Item .env.example .env
notepad .env
```

Заполните значения в `.env`:

| Переменная | Назначение |
| --- | --- |
| `DB_NAME`, `DB_USER` | Имя базы и пользователь MySQL |
| `DB_PASSWORD` | Пароль пользователя MySQL |
| `DB_ROOT_PASSWORD` | Пароль администратора MySQL |
| `JWT_SECRET_KEY` | Секретная строка для подписи токенов, не короче 32 байт |
| `ADMIN_LOGIN` | Логин системного администратора |
| `ADMIN_PASSWORD` | Пароль системного администратора |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота (обязателен) |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@` (необязательно, для ссылки привязки) |
| `TELEGRAM_CHAT_ID` | Числовой ID чата или `@channel`, куда бот пишет напоминания |
| `ADMIN_TELEGRAM_CHAT_ID` | Личный чат администратора для обращений; если не задан, используются `TELEGRAM_CHAT_ID` или привязанный Telegram администратора |
| `TIMEZONE` | Единый часовой пояс для сроков и просрочек, например `Europe/Moscow` |
| `REMINDER_DAYS` | За сколько дней напоминать (по умолчанию 3) |
| `CORS_ORIGINS` | Разрешённые origin фронтенда через запятую |
| `WEB_PORT` | Порт веб-панели |

Системный администратор создаётся при запуске приложения из `ADMIN_LOGIN` и `ADMIN_PASSWORD`; через панель его учётная запись не изменяется. Бот должен быть добавлен в чат из `TELEGRAM_CHAT_ID` и иметь право писать в него. Обращения отправляются в `ADMIN_TELEGRAM_CHAT_ID`, если он задан; иначе используется чат из `TELEGRAM_CHAT_ID`, а затем Telegram, привязанный к админской учётной записи. Не используйте демонстрационные пароли в реальном окружении.

Соберите образ и запустите API вместе с MySQL:

```powershell
docker compose up --build -d
```

При старте контейнер ждёт готовности MySQL, применяет миграции Alembic, затем запускает API, планировщик напоминаний и Telegram-бота. Состояние и логи:

```powershell
docker compose ps
docker compose logs -f app
```

Остановить контейнеры, сохранив данные:

```powershell
docker compose down
```

Данные MySQL хранятся в Docker volume `dbdata`. Команда `docker compose down -v` удаляет этот volume вместе с данными.

## Привязка Telegram к аккаунту

1. Откройте Telegram-бота и отправьте `/link`; бот пришлёт одноразовый код на 10 минут.
2. Войдите в панель, откройте «Подключить Telegram» и введите этот код.
3. Отвязать аккаунт: команда `/unlink` в боте или `DELETE /api/v1/auth/telegram-link`.

## Веб-панель

Веб-интерфейс находится в `frontend/` и отдаётся nginx из Docker Compose. Откройте `http://localhost/`: после входа панель автоматически направит пользователя на страницу его роли. Для входа и создания аккаунтов используются логин и пароль.

Страницы администратора и пользователя используют общую клиентскую логику из `frontend/script.js` и API по адресу `/api/v1`. Таблицы платежей, отметка оплаты, история, обратная связь и привязка Telegram работают через API-эндпоинты. Обращения обычных пользователей доставляются администратору в Telegram. Внешний вид задаёт `frontend/style.css`, файлы логотипа находятся в той же папке. Выбор светлой или тёмной темы сохраняется в браузере.

Чтобы обновить интерфейс, измените файлы в `frontend/`: Compose подключает эту папку к nginx как статические файлы. После изменений перезагрузите страницу; если отображается старая версия, очистите кэш браузера. Обновление клиентской части не требует менять API, пока сохраняются используемые `script.js` поля, события и эндпоинты.

Администратор может открыть платёж из таблицы, изменить его и восстановить ранее прекращённый регулярный платёж. Чеки форматов PNG, JPEG, WEBP и PDF размером до 2 МБ хранятся вместе с периодом оплаты в базе данных. Список отделов общий для пользователей и сохраняется в базе; удаление отдела из списка не изменяет уже созданные платежи. Календарь открывается нажатием на период над сеткой и позволяет перейти к выбранной дате. «Отказано / Просрочка» рассчитывается автоматически по сроку и фактической дате оплаты.

## API

Через Docker Compose (nginx на `WEB_PORT`, по умолчанию 80):

- Панель: `http://localhost/`
- API: `http://localhost/api/v1`
- Swagger UI: `http://localhost/api/v1/docs`
- OpenAPI: `http://localhost/api/v1/openapi.json` (копия также в `openapi.json`)

Если запускаете только приложение без nginx (`python -m app.main`), порт API — `8000`.

Для защищённых запросов передавайте JWT в заголовке `Authorization: Bearer <accessToken>`.

| Метод | Эндпоинт | Назначение |
| --- | --- | --- |
| POST | `/auth/login` | Вход по логину и паролю |
| GET | `/auth/me` | Текущий пользователь |
| POST | `/auth/logout` | Завершение сессии |
| POST | `/auth/telegram-link` | Привязка Telegram по коду, который пользователь получает от бота командой `/link` |
| DELETE | `/auth/telegram-link` | Отвязка Telegram от аккаунта |
| GET, POST | `/recurring-payments` | Список и создание регулярных платежей (создание — админ) |
| PATCH | `/recurring-payments/{id}` | Изменение шаблона и неоплаченных периодов (админ) |
| DELETE | `/recurring-payments/{id}` | Прекращение платежа и его напоминаний с сохранением истории (админ) |
| POST | `/recurring-payments/{id}/restore` | Восстановление прекращённого платежа (админ) |
| GET | `/payment-occurrences` | Список периодов (фильтры: статус, валюта, даты) |
| GET, PATCH | `/payment-occurrences/{id}` | Период; отметка или отмена оплаты, исправление даты |
| GET | `/payment-occurrences/{id}/receipt` | Получение приложенного чека |
| GET | `/payments/summary` | Итоги по валютам |
| GET, POST | `/departments` | Список и создание отделов (создание — админ) |
| DELETE | `/departments/{id}` | Удаление отдела из общего списка (админ) |
| GET, POST | `/users` | Список и создание пользователей (админ) |
| PATCH, DELETE | `/users/{id}` | Изменение и удаление пользователя (админ) |
| GET | `/audit-log` | Журнал авторизации и действий (админ) |
| POST | `/feedback` | Отправка обращения пользователя администратору в Telegram |

## Сценарий демонстрации

1. Заполните `TELEGRAM_CHAT_ID` в `.env`, добавьте бота в чат, перезапустите `app`.
2. Войти администратором и добавить регулярный платёж со сроком через 3 дня или меньше.
3. Получить напоминание в Telegram-чате.
4. Войти пользователем и отметить оплату (в панели или кнопкой в боте).
5. Показать просроченный платёж, исправить фактическую дату оплаты и убедиться, что просрочка пересчиталась.
6. В панели подключить Telegram: отправить боту `/link`, ввести полученный код; затем отправить обращение и проверить, что оно пришло администратору в Telegram.
7. Показать следующий период с отдельным статусом.
